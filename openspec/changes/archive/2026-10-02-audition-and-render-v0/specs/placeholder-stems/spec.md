## Purpose

Provides a committed placeholder piece whose stems can be regenerated byte-for-byte on any machine, so audio rendering can be developed, heard and tested without committing audio or depending on real recordings.

## ADDED Requirements

### Requirement: Placeholder piece
The repository SHALL contain a placeholder piece at `pieces/placeholder/`: a valid manifest (`manifest.json`) and a synthesis recipe for every clip in its catalogue. The manifest SHALL include at least three slots, at least two sections, a clip whose stem has a tail of at least one bar beyond its body, a clip whose sound makes bar alignment audible (for example a click on each beat), a sustained clip, a tempo or meter change, and an exclusion pair. No placeholder audio file SHALL be committed.

#### Scenario: Manifest is valid
- **WHEN** `spite validate pieces/placeholder/manifest.json` is run
- **THEN** it exits 0

#### Scenario: Every clip has a recipe
- **WHEN** the recipes are compared with the manifest's clip catalogue
- **THEN** every clip id has exactly one recipe and no recipe names an unknown clip

### Requirement: Reproducible generation
`pnpm stems:placeholder` SHALL synthesize every clip's stem from its recipe as a 48 kHz WAV file and write it to `.stems/<hex>.wav`, where `<hex>` is the sha256 of the file's bytes. Generation SHALL be deterministic and use only arithmetic whose results ECMAScript specifies exactly, so the same recipe produces identical bytes on every machine and runtime. `.stems/` SHALL be ignored by git.

#### Scenario: Same bytes everywhere
- **WHEN** the placeholder stems are generated twice, including once inside a context with only standard ECMAScript globals
- **THEN** every stem's bytes are identical across the runs

#### Scenario: Not tracked
- **WHEN** stems have been generated and the repository's tracked files are listed
- **THEN** no file under `.stems/` is tracked, and `git check-ignore` matches `.stems/`

### Requirement: Hash verification
Generation SHALL compare each stem's hash with the hash its clip declares in the placeholder manifest. If every hash matches, it SHALL report the number of stems written and exit 0. If any differs, it SHALL list each mismatching clip id with the expected and actual hash and exit 1. Generation SHALL accept an explicit `--update` flag that rewrites the manifest's hashes to the generated values. This is the only supported way to change them after editing a recipe.

#### Scenario: Hashes match
- **WHEN** `pnpm stems:placeholder` is run on an unmodified checkout
- **THEN** it exits 0 and `.stems/` contains one WAV per clip, named by its hash

#### Scenario: Recipe drift detected
- **WHEN** a recipe is edited without `--update` and generation is run
- **THEN** it names that clip with its expected and actual hash and exits 1

#### Scenario: Deliberate update
- **WHEN** a recipe is edited and generation is run with `--update`
- **THEN** the manifest's hash for that clip is rewritten, and a subsequent run without `--update` exits 0
